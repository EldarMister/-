# Время работы

Новая таблица `location_schedules` добавляется совместимой миграцией `server/admin-schedules-schema.sql`. У существующих точек недельное ограничение изначально не включено; поля `hours` и `opens_at` сохраняются. Сотрудник с `schedules.edit` открывает «Время работы», задаёт интервалы и явно включает ограничение приёма заказов.

Часовой пояс фиксирован: `Asia/Bishkek`, UTC+6. Дни пронумерованы от понедельника до воскресенья. Пустой список интервалов означает выходной. Если окончание раньше начала, интервал продолжается на следующий день. Одинаковое начало и окончание означает сутки. Для перерывов задаются несколько интервалов. Сервер проверяет пересечения, в том числе между воскресеньем и понедельником. Начало включено в интервал, окончание исключено.

Создание заказа проверяет включённое расписание внутри транзакции. Вне интервалов API возвращает 409 с понятным сообщением. Расписание не изменяет уже созданные заказы. При редактировании точки и её существующего текстового поля недельное расписание не теряется. Изменения пишутся в журнал и обновляют административную панель через SSE. Одновременные изменения защищены номером версии; при конфликте нужно обновить редактор.

Для отката нового ограничения достаточно выключить «Принимать заказы только в рабочие интервалы». Исходный текст часов работы остаётся в базе. Старые исключения по датам в модели проекта отсутствовали; фиктивные исключения и история не создаются. Витрина продолжает показывать существующий текст часов; при включении недельного графика сотруднику необходимо согласовать этот текст в карточке точки.

Проверка: `node --import tsx --test tests/schedule-rules.test.ts`. Тесты покрывают часовой пояс, границы закрытия, переход через полночь и неделю, перерывы, круглосуточный режим, неверные часы и пересекающиеся интервалы.
