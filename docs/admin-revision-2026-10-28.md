# Доработка административной панели · 28 октября 2026

## Интерфейс и языки

Каркас повторно собран по исходному shadcnstore-шаблону: шапка 56px, сворачиваемая навигация 16rem, локальный Inter, компактный бренд, командный поиск Ctrl/Cmd+K, карточки с `CardAction`/`CardFooter`, график и таблица последних заказов. График переключает выручку и количество заказов за 7/30/90 дней, использует серверную аналитику и доступен только с соответствующим правом. Все операции существующих разделов сохранены.

Админка использует общий выбор языка сайта: русский, кыргызский, английский, казахский, узбекский. В `app/admin/messages.json` — 854 авторских исходных сообщения с четырьмя переводами. Переводятся вход, навигация, формы, диалоги, статусы, права, ошибки, уведомления и подсказки PWA. Выбор сохраняется в cookie/localStorage и синхронизируется между вкладками. Даты используют Asia/Bishkek. Названия товаров, категорий и введённые клиентские данные остаются исходными. Для отсутствующей исторической категории API возвращает отдельный `categoryMissing`, поэтому настоящее название «Категория не записана» не подменяется переводом.

## Заказы, звук и уведомления

Звук включается явной кнопкой в общей шапке; рядом есть проверка звука. Громкость и выключение доступны в профиле. Активация необходима после открытия новой вкладки из-за правил браузера. Локальная дедупликация использует Web Locks либо атомарную транзакцию IndexedDB. Пропущенная пачка заказов вызывает один сигнал. Отозванные права и смена сотрудника очищают приватное состояние и останавливают доступ к уведомлениям.

Колокольчик открывает историю с переходом в заказ и персональными отметками прочтения. Журнал сохраняется на сервере, первоначальная загрузка истории выполняется без сигнала. Восстановление соединения догружает пропущенные события, включая поздно завершившиеся транзакции. Загруженная история обновляет отметки прочтения из другой вкладки; дубликат SSE не возвращает прочитанное сообщение в непрочитанные. Команда «Прочитать все» ограничена снимком списка до нажатия и не захватывает одновременно пришедший заказ.

В `server/schema.sql` добавлены `admin_order_events`, `admin_order_event_reads` и отметка миграции `2026-10-28-order-notification-history`. Запись события и создание заказа находятся в одной транзакции. История прежних заказов искусственно не создаётся. API использует снимки видимости PostgreSQL, а не предположение о последовательности номеров заказов.

Общий SSE-канал обновляет открытые списки, карточку заказа, обзор, аналитику, персонал и журнал действий. При обрыве соединения предусмотрено восстановление и резервная синхронизация. Проверки прав выполняются сервером при запросах и отправке событий.

## PWA

Админка имеет отдельный manifest и worker v6 с областью `/admin/` и стартовой страницей `/admin/app`. Установка и ручное обновление доступны из интерфейса. Offline-экран поддерживает все пять языков. В кэше находятся только публичные ресурсы: заказы, контакты, API и персонализированный HTML не кэшируются.

Системный Web Push использует язык устройства и проверку актуальных прав получателя. Для доставки в фоне на рабочем сервере нужны HTTPS и `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`; эти ключи не подменяются тестовыми. При отсутствии настройки интерфейс честно показывает состояние. Инструкция конфигурации: [admin-pwa.md](admin-pwa.md).

- `npm test`: типы, production-сборка, существующие тесты и админские проверки прошли. После финальных изменений дополнительно выполнены финальная сборка, TypeScript, 27 админских тестов и 13 проверок настоящего worker-кода.
- Финальный запуск `node --test tests/*.test.mjs`: 27 пройдено, 10 интеграций ожидаемо пропущено без переменных подключения. Эти 10 интеграций запускались отдельно с подключением к тестовой базе; пропуски не считаются проверкой API. Существующая TS-группа: 65 пройдено.
- 10 сценариев API запускались на отдельном PostgreSQL, включая права, SSE, расписание, каталог, настройки, загрузку файлов, награды, аналитику и сохранность заказов при удалении/перезапуске. Проверка уведомлений создаёт и удаляет отдельную временную БД.
- В отдельном тесте 150 пропущенных событий загружены страницами 100+50; незавершённая транзакция скрыта; поздний commit более раннего заказа появляется в следующей загрузке; прочтение изолировано по сотрудникам; после отзыва прав API возвращает 403.
- Lint: 0 ошибок; остаются 17 предупреждений об использовании обычных изображений.
- В браузере новый заказ появился без перезагрузки в каталоге/уведомлении и списке заказов второй вкладки. Изменение статуса через другую сессию обновило открытый диалог и вторую вкладку.
- В браузере выполнено переключение EN → KY при открытом несохранённом товаре: черновик сохранился, подписи и подтверждение закрытия перевелись. Черновик закрыт без сохранения.
- Ручное обновление PWA применено в браузере. После остановки только тестового web-сервера перезагрузка показала безопасный английский offline-экран с сохранённым выбором языка и без приватных данных.

Браузерная проверка использует локальные API 4100, web 4180 и отдельную PostgreSQL 5544. Production не публиковался. Нативная установка в ОС и реальная доставка Web Push без серверных VAPID-ключей не заявляются проверенными; физическая громкость динамиков не измерялась.
