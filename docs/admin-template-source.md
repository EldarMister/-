## Что использовано

`app/admin/ui/index.tsx` адаптирует структуру и `data-slot` компонентов Card, Table, Button и Badge. CSS переносит нейтральные OKLCH-токены светлой и тёмной темы, радиусы, размеры, таблицы, композицию карточек и боковой навигации из Next.js-версии. `AdminPanel` собирает новый каркас: сгруппированное меню, отдельная шапка, хлебные крошки, профиль сотрудника и содержимое экранов. Каталог пересобран в таблицы с отдельными формами; точки используют карточки с картой в редакторе.

UI адаптирован к существующему CSS-окружению витрины: токены ограничены `html.admin-page`, чтобы не менять клиентское приложение. Не устанавливались второй React, другой сервер, конкурирующая UI-библиотека или демонстрационные приложения. Нативный `dialog` обеспечивает модальность, удержание фокуса и возврат фокуса; для него использованы визуальные правила шаблона. Отдельно добавлено предупреждение о несохранённых полях. Данные Mail/Chat/Pricing, рекламные ссылки и пользовательский редактор темы не перенесены.

## Шрифт

Для соответствия `src/lib/fonts.ts` исходного шаблона Inter подключён локально: `public/admin/fonts/inter-latin-cyrillic.woff2`. Полный variable-файл получен из [официального проекта Inter](https://github.com/rsms/inter/blob/master/docs/font-files/InterVariable.woff2), лицензия сохранена рядом в `OFL.txt`. Внешний запрос к Google Fonts при открытии админки не требуется; кириллица и латиница используют один файл.

## Доработка соответствия шаблону 28 октября 2026

Каркас повторно сопоставлен с `app-sidebar.tsx`, `site-header.tsx`, `section-cards.tsx`, `chart-area-interactive.tsx` и `data-table.tsx` оригинала. Использованы шапка высотой 56px, сворачиваемое меню шириной 16rem, компактный блок бренда, командный поиск разделов с Ctrl/Cmd+K, структура `CardAction`/`CardFooter` и нейтральные градиенты карточек. Колокольчик, звук, язык и тема доступны из общей шапки.

Главная содержит реальные показатели, переключаемый график выручки/заказов за 7, 30 или 90 дней и таблицу последних заказов с вкладками статусов. Значения графика приходят из существующего серверного расчёта аналитики; график показывается только при `analytics.view`, список заказов — при `orders.view`. Демонстрационные значения оригинала не перенесены. Поиск показывает только доступные сотруднику разделы и открывает выбранный раздел клавишей Enter.

## Каталог и данные

Товары, категории, акции и точки читаются с сервера страницами по 24 записи. Поиск и фильтры передаются в API. В формах категорий нет slug и внутренних идентификаторов: сервер создаёт slug автоматически, переименование его не меняет. В связанных полях используются названия категорий. Права действий управляют видимостью кнопок; сервер независимо проверяет каждый запрос.

Программа наград пересобрана в `LoyaltyWorkspace`: отдельные вкладки для Coin, NFT и настроек программы. Очередь загружает по 25 записей выбранного вида и статуса; сводка берётся из реального `loyalty/overview`. Старые параллельные загрузки девяти очередей и запрос списка клиентов не используются. В карточке сохраняется ручной процесс принятия заявки, отклонения и подтверждения перевода. UUID скрыт; адрес кошелька и хеш транзакции доступны в карточке, поскольку необходимы для выполнения перевода. Все восемь настроек наград сохранены, параметры контракта и метаданных находятся в «Дополнительно». Просмотр и редактирование независимо проверяются сервером.
