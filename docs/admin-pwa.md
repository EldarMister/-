# Установка панели и политика PWA

Обычный адрес панели — `/admin`. Установленное приложение запускается по `/admin/app`: этот адрес находится внутри `scope: /admin/`, даже если маршрутизатор перенаправляет `/admin/` на `/admin`. Manifest имеет отдельный идентификатор и иконки 192×192, 512×512 и maskable. Административный service worker зарегистрирован только для `/admin/` и не меняет область действия клиентской витрины.

В production требуется HTTPS. Установка и разрешение на системные уведомления запрашиваются действиями сотрудника в профиле. Если установка браузером не поддерживается, интерфейс показывает инструкцию для Chrome/Edge или Safari. Поддержка системных уведомлений зависит от браузера и устройства; закрытое приложение не гарантирует доставку, соединение или произвольный звук.

## Что хранится на устройстве

Service worker `public/admin/sw.js` версии v5 сохраняет только публичную offline-страницу, иконки, логотип, локальные шрифты и файлы JS/CSS с хешами из `/_next/static/`. Кэш ресурсов ограничен 60 файлами. Ответ должен иметь статус 200 и ожидаемый тип содержимого. Ответы с `private`, `no-store`, `Set-Cookie`, вариацией по Cookie/Authorization и перенаправления не сохраняются.

Авторизованные API, заказы, контакты, отчёты, загрузки, неизвестные изображения и персонализированный HTML не кэшируются. Навигация панели обращается к сети с `no-store`. При сетевой ошибке показывается общая offline-страница; данные сотрудников в ней отсутствуют. Операции не ставятся в скрытую очередь. Без ответа сервера сохранение не считается успешным.

## Обновления и уведомления

Новая версия worker ожидает явного действия «Обновить приложение». При установке нет автоматического `skipWaiting`. Перед перезагрузкой сотруднику предлагается сохранить открытые формы. Старые кэши удаляются только по административным префиксам; кэши витрины и других приложений сохраняются.

Фоновое уведомление содержит общий текст и проверенный номер записи заказа. Имя, телефон, адрес, сумма и произвольный текст из payload не выводятся. Нажатие открывает `/admin/app?order=…`, повторно проходя обычную проверку сессии и доступа в панели. Чужие origin, пути вида `/administrator` и некорректные URL отклоняются. При наличии открытого окна панели оно используется повторно. Произвольные параметры URL не пересылаются.

Серверные VAPID-ключи и контакты настраиваются отдельно по инструкции запуска; закрытый ключ не передаётся браузеру. Звук в открытой панели и Web Push остаются независимыми настройками.

## Проверки

`node --test tests/admin-pwa.test.mjs` выполняет 12 тестов реального JavaScript service worker в изолированном VM-окружении с событиями install/activate/fetch/message/push/notificationclick. Проверяются область manifest, реальные размеры PNG, политика публичного кэша, границы кэша ресурсов, offline fallback, ручное обновление, отсутствие персональных данных и безопасный переход к заказу. Эти проверки не заменяют проверку установки и доставки Web Push в конкретном браузере и ОС.

Во встроенном браузере отдельно проверены загрузка `/admin/app` и настоящее обновление worker v2→v3: появление баннера, предупреждающий диалог, явное «Обновить сейчас», перезагрузка с сохранённой сессией и исчезновение баннера. [Снимок диалога](../outputs/admin-rebuild/pwa-update.jpg). Offline fallback реально проверен после остановки тестового web-сервера: перезагрузка показала общую страницу «Нет соединения» из кэша. [Снимок offline-страницы](../outputs/admin-rebuild/pwa-offline.jpg). Нативная установка в ОС и внешняя доставка Web Push не проверялись; VAPID-ключи не настроены.

Manifest витрины по прежнему `/manifest.webmanifest` и с прежним содержимым выдаётся через `app/manifest.webmanifest/route.ts` из `app/storefront-manifest.ts`. Это сохраняет клиентское PWA и позволяет странице админки указать собственный manifest: исходный корневой file-based manifest имел приоритет над конфигурацией вложенной страницы. В браузере подтверждён именно `/admin/manifest.webmanifest` для `/admin/app`; SSR-тесты проверяют оба адреса панели и неизменный manifest каталога.
